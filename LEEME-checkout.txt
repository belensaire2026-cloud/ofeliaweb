CHECKOUT DE OFELIA ST — que hay que configurar
===============================================

La web ya tiene carrito, pantalla de compra, cupon de descuento y
envios. Lo unico que falta son las credenciales. Van cargadas en
Cloudflare como "variables de entorno", NUNCA escritas dentro de
index.html ni subidas al repositorio.

Cloudflare -> tu proyecto -> Settings -> Environment variables


1) MERCADO PAGO  (para poder cobrar)
------------------------------------
  MP_ACCESS_TOKEN   <- marcala como "Secret" / "Encrypt"
  SITE_URL          <- https://tudominio.com  (sin barra al final)

  Al crear la aplicacion en Mercado Pago, elegi:
     Solucion: Checkout Pro

  IMPORTANTE: el codigo usa /checkout/preferences, que es la API
  clasica de Checkout Pro. La API nueva de "Orders" pide el medio
  de pago por adelantado y no sirve para un pago con redireccion,
  por eso no se usa. Si en el panel de Mercado Pago te hace elegir
  tipo de API, la que corresponde es Preferences.

  De donde sale el access token:
  mercadopago.com.ar/developers -> Tus integraciones -> Crear
  aplicacion -> Credenciales de produccion -> Access Token.
  Ese valor no se lo mandes a nadie, ni por mail ni por WhatsApp.
  Se pega directo en Cloudflare.

  Mientras MP_ACCESS_TOKEN no este cargada, el boton de pagar avisa
  que el pago online todavia no esta activo. No rompe nada.


2) CORREO ARGENTINO  (para calcular el envio)
---------------------------------------------
  CORREO_USER_TOKEN       <- usuario de la API
  CORREO_PASSWORD_TOKEN   <- contrasena de la API  (marcala Secret)
  CORREO_CUSTOMER_ID      <- tu numero de cliente de MiCorreo
  CORREO_CP_ORIGEN        <- tu codigo postal, desde donde despachas
  CORREO_ENTORNO          <- "prod" (o "test" para el ambiente de prueba)

  Las credenciales de la API las da Correo en
  correoargentino.com.ar -> MiCorreo -> Integrate a PAQ.AR.

  El CUSTOMER_ID no es lo mismo que el usuario de la API. Es el
  identificador de tu cuenta de MiCorreo, de la forma "0000550997".
  Si no lo tenes a mano, pediselo a Correo o sacalo del panel de
  MiCorreo. Sin ese dato, /rates y /agencies devuelven
  402 "Cliente FAP no identificado".

  Mientras falte cualquiera de las cinco variables, la web NO se
  rompe: cotiza con estas tarifas fijas, que se cambian arriba de
  todo en src/envios.js:
      a sucursal   $6.500
      a domicilio  $8.500

  El paquete que se cotiza esta definido en src/envios.js, en la
  constante PAQUETE: 500 g, 6 x 16 x 12 cm. Si empezas a mandar
  cajas mas grandes, cambialo ahi.


3) CUPONES DE DESCUENTO
-----------------------
  Los codigos viven en la constante CUPONES y estan duplicados en
  DOS lugares que tienen que decir siempre lo mismo:
      index.html      (arriba de "let coMedio")
      src/checkout.js (arriba de SHEET_CSV)

  Formato: CODIGO: { pct, vence }, con vence en AAAA-MM-DD.
  Hoy hay uno: WARMI10, 10%, vence 2026-12-31.

  El descuento se aplica solo a las piezas, nunca al envio, y el
  servidor lo vuelve a validar antes de cobrar.


4) SI ALGO SALE MAL DESPUES DEL PUSH
------------------------------------
  El archivo wrangler.jsonc es el que le dice a Cloudflare como
  publicar la web. Si despues de subirlo la pagina deja de verse:
    - Cloudflare -> tu proyecto -> Deployments -> "Rollback" a la
      version anterior. Vuelve a andar al instante.
    - Y avisame, que lo arreglo.
  El nombre que dice "name" en wrangler.jsonc TIENE que ser igual
  al del proyecto en Cloudflare. Si no coincide, no se actualiza.


5) PROBAR
---------
  - Agrega algo al carrito y entra a "Finalizar compra".
  - Con "Retiro en persona" el envio es $0.
  - Con domicilio o sucursal, escribi un CP y fijate que aparezca
    el precio del envio. Si aparecen $6.500 / $8.500 clavados, es
    que todavia esta usando las tarifas fijas.
  - Proba el cupon WARMI10 y mira que el total baje un 10%.
  - Con MP en modo prueba, usa las tarjetas de test de Mercado Pago.


ALGO IMPORTANTE SOBRE LOS PRECIOS
---------------------------------
El precio nunca se toma de lo que manda el navegador: antes de cobrar,
el servidor vuelve a leer tu planilla publicada y valida precio y
stock de cada pieza. Si alguien intenta cambiar el precio desde la
consola del navegador, el pago se rechaza.
Esto significa que LA PLANILLA MANDA. Si un precio esta mal ahi,
esta mal en el cobro.
